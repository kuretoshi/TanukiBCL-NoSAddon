# NGワードと音声認識の分担（0.1.0-β17）

PC通常版・Lite版・.NET版は各自のマイクを自分のPCで認識する。ホストは自分のマイクと、Web／モバイルと確認できた参加者の受信音声だけを認識する。この分担はNGワードとヒーローの「変身」で共通。参加方法が不明な音声をPCと推測してホストへ回すことはしない。

同じプレイヤーが両能力を持つ場合も認識器は一つにまとめる。日本語モデルはプロセス内で共用し、対象者がいない端末では読み込みを始めない。判定結果だけをローカルのゲームへ渡し、変身・死亡はアドオンのRPCで同期する。一般の文字起こしや録音を保存・アップロードしない。

## リストと配布

初回起動時、ゲームフォルダの `TanukiBCL/NGWords.txt` が存在しなければ[テンプレート](../addon/Resources/NGWords.template.txt)をコピーする。既存ファイルは上書きしない。UTF-8で一行に一語を記載する。`#`で始まる行はコメント。必要なら `表示名|読み方|別の読み方` を指定できる。

β17では、NGワード設定にホスト専用のファイル操作を追加している。ロビーとフリープレイの両方で使用できる。

- **参照**：Windowsのファイル選択画面でリストを指定する。内容を検証してから選択を変更し、次の試合から読み込む。選択したファイルは編集・上書きしない。選択先は `TanukiBCL/NGWordSource.txt` に保存し、次回起動時も使用する。
- **テンプレートを保存**：保存ダイアログで任意の場所へテンプレートを保存する。
- **現在の設定を保存**：現在選択しているNGワードリストを、コメント・読み方も含めて任意の場所へ保存する。出力先を現在の読み込み元へ切り替える操作ではなく、ロビーのオン／オフ設定も含めない。

キャンセルした場合は変更しない。不正なリストや読めないファイルを指定した場合も、それまでの選択を維持する。既存ファイルへの保存ではWindowsの上書き確認を表示する。ダイアログを別スレッドで実行し、ゲームの作業フォルダーを変更しない。

```text
インポスター|いんぽすたー
タスク|たすく
投票|とうひょう
```

ロビー設定のNGワードで「NGワードを割り当てる」をオンにすると、試合開始時にホストのファイルを読み、全陣営の参加者へモディファイアとワードをランダムに割り当てる。通常の陣営別割当数はこの全員配布に使用しない。初期状態はオフ。リストのワード数が参加者数以上なら表示名が重複しないよう配り、不足時だけ循環して重複させる。ファイルを途中で編集しても進行中の試合には反映しない。

各プレイヤーの画面上部に自分のワードと認識状態を表示する。本人のワードを含む確定認識結果を受け取ると本人が自殺する。途中結果では死亡させない。会議中の判定は設定で切り替え可能（初期値オン）。ミュート・未接続・死亡・試合終了中は新しい発言を判定しない。リストは1～256語、各表記2～32文字、読み方は二つまで。空リストや不正な項目は受け付けない。

β17には「自分のNGワードを隠し、他の人に表示する」設定も追加。初期値はオフで、従来の自己表示を維持する。オンにすると自分の画面上部にはワードを出さず、認識状態だけを残す。他の生存・接続中のプレイヤーのワードを、通常時は頭上の名前より上、会議中は各投票プレート内の名前のすぐ上に表示する。自分のワードは会議プレートにも表示しない。会議中の音声判定がオフでもワードの表示は継続する。

名前や役職名の本文・位置は変更せず、専用のテキストを名前の子オブジェクトとして表示する。通常時は名前表示に追従するため、名前が隠れる壁越し・ベント内・透明化中などにワードだけを表示しない。死亡・切断・モディファイア解除時にはワード表示を削除し、会議の開始・終了時には表示先を作り直す。

## 互換性と検証

分担の判別には参加者の更新版ベタクルが送る参加方法を使う。古いPC版をホスト認識へ自動で戻すことはしない。古いWeb版など、参加方法を確認できない場合は認識準備中・未接続と表示する。音声認識連携のローカルプロトコルは2へ更新しているため、アドオンとベタクルを揃える必要がある。

PC版ではホスト／非ホストの認識対象、同一プレイヤーの認識器共用、参加方法の期限切れ、重複結果、ミュート前の音声の破棄、試合退出の自動テストを通過。.NET版の分担・表記揺れ・連携プロトコルの自己テストとビルド、Web／モバイル版のビルドと210件のテストも通過した。

NoSのフリープレイで全員配布、ワードと認識状態の表示、誤った判定番号の拒否を確認。制御した判定結果を使い、変身とNGワードの併用、およびNGワードによる死亡処理まで確認した。この確認では実マイクの単語認識は試していない。複数端末間の実音声、人数を増やした負荷、誤認識率は別途確認が必要。テスト用に変更したゲーム設定は元に戻している。

## プレイヤー入力方式

「ゲーム開始時に全員がNGワードを入力する」をオンにすると、ファイルの代わりに試合開始直後の入力画面で全員から一語ずつ集める。「NGワードを割り当てる」もオンにする。初期状態はオフで、既存のファイル方式を維持する。

- 2〜32文字。`ワード|読み方|別の読み方` にも対応する。確定後の変更はできない。
- 全員の確定を待ち、ホストが各投稿を一度ずつランダムに割り当てる。自分の投稿は自分に配らない。同じ文字列を別の人が投稿した場合は重複し得る。
- 待機中は移動・通常の行動とNGワード音声判定を停止する。入力画面はイントロ終了後に表示する。
- 切断・死亡した参加者とその投稿を待機対象から外す。2人未満ではこの試合の配布を中止する。ホスト変更時も待機を解除し、この方式の配布を中止する。
- この収集処理はアドオン内RPCで動作し、リストファイルの読み込み・保存は行わない。既存の自分のワード非表示設定を適用できる。

割り当てロジックの検証: `dotnet run --project tests/NGWordSubmission/NGWordSubmissionTests.csproj`。複数端末での入力UI・待機解除・同期はゲーム内で確認する。


### 割り当て人数

「NGワードの割り当て人数」で「全員」または1〜24人を選べる。初期値は全員。実際の参加者数を超える指定は参加者数までに抑える。ファイル方式・プレイヤー入力方式の両方に適用し、対象者は陣営に関係なくランダムに選ぶ。

入力方式では、配布人数を減らしても全員が入力・確定する。全員の投稿から、対象者自身が書いたものを除いて配り、同じ投稿は再利用しない。対象者が1人でも他の参加者の投稿を配れるが、参加者自体が1人の場合は配布しない。

入力方式では役職紹介後の開始ルーチンを待機させ、黒い背景の中央に閉じるボタンのない入力画面を表示します。確定後は入力欄を消して「しばらくお待ちください」と確定人数を表示し、全員の確定・配布後にスポーンとゲーム開始へ進みます。設定の表示確認も入力→待機を確認でき、待機画面の「表示確認を終了」で戻れます。

β17ではローカルゲーム内の表示確認で、黒背景・閉じるボタンなしの入力画面と確定後の待機画面を確認済み。複数端末での開始・全員確定・待機解除は未検証。
