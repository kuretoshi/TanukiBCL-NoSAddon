# ダイイングボイスメッセージ

通常役職に追加するモディファイア。死亡後に自動録音し、死亡地点に音声メッセージを残す。

- 録音時間：1〜30秒、初期値5秒。
- 「録音音声をループ再生」は初期値オフ。オンの場合、生存者が範囲内にいる間だけ繰り返す。範囲外・会議・死亡・ミュートで停止する。
- 再生範囲：0.5〜10、初期値2.5。
- 録音終了後、死亡地点に目印を表示。遺体がなくなっても地点は移動しない。
- 「設置地点のアイコンを生存者に表示」で生存者への目印の表示を切り替えられる（初期値オン）。幽霊には設定にかかわらず表示する。オフでも録音・範囲内での再生は行う。
- 生存者が範囲へ入ると、その人の端末だけでラジオ風に再生する。範囲外へ出ると停止し、入り直すと最初から再生する。
- 録音終了時点ですでに範囲内にいる生存者にも再生する。
- 会議中は再生しない。会議中の死亡でも録音時間は進む。
- 死亡者のマイクミュートは解除しない。受信側のミュート・音量設定も反映する。
- 録音開始から受信できた音声だけを使う。録音終了後に接続した人は、その後の幽霊の会話を録音しない。
- 音声は各受信者のメモリにのみ保持する。試合終了・役職解除・復活・送信者の切断で破棄する。
- 複数人同時の録音に対応。Web・モバイル版もホストから受け取る役職情報を使う。

## 対応版

タヌキ丼 0.1.0-β10 と、タヌキのベタクル通常版・Lite版・.NET版の3.2.35、またはWeb・モバイル版3.27を組み合わせて使用します。
Web・モバイル版の土台はPC版3.2.24相当です。今回の音声メッセージ対応を追加しており、PC版3.2.35の全機能との同等性を意味しません。
アドオンだけを更新しても、旧ベタクルでは音声メッセージを再生できません。

## 検証

PC側：`node scripts/test-dying-voice.mjs`。実際の受信状態ファイルの検証、録音区間、時間上限、ラジオフィルター、範囲・生死・会議条件、出入りの再生、ミュート、破棄を確認する。

Web・モバイル側の録音処理も同じテストを、`TANUKI_DYING_VOICE_SOURCE` に当該TypeScriptファイルを指定して実行できる。

対応ベタクルを使い、実ゲームでの死亡後の録音・再生が動作することを確認済み。

試合終了イベントでアドオンの設置地点・目印を消去し、最後のメッセージが消えたときに当該NoSプロセスの連携JSONも削除する。音声クライアントはゲーム終了状態または空の役職情報を受け取ると、再生を停止して録音用・再生用バッファを破棄する。
